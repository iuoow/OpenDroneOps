# UI/UX 总则

## 产品定位

OpenDroneOps 不是传统 CRUD 管理后台，也不是装饰性“科技大屏”，而是：

> 地图驱动的无人机实时运营工作台：地图负责态势，时间线负责过程，侧栏负责上下文与操作，列表负责管理。

## 首要用户问题

任何时刻，用户都应能快速回答：

1. 哪些设备需要关注？
2. 设备在哪里？
3. 数据是否仍然新鲜？
4. 刚才发生了什么？
5. 当前操作进行到哪一步？
6. 下一步应该做什么？

## 设计原则

### 态势优先

默认首页以地图和实时状态为核心，不在首屏堆叠大量 KPI 图表。

### 状态可解释

“在线”必须与以下状态分开：

- 浏览器实时连接状态；
- MQTT 设备连接状态；
- 遥测最后更新时间；
- 数据是否过期；
- 指令是否仍在执行。

### 操作可追踪

每个异步操作都应显示：已提交、处理中、已发送、设备已接受、执行中、成功、失败或超时。

### 风险分级

- 低风险：按钮确认；
- 中风险：参数复核；
- 高风险：状态前置检查、明确风险文本、二次确认和审计；
- MVP 禁止真实飞行控制。

### 实时但不躁动

- 新告警脉冲一次；
- 数值平滑更新；
- 地图位置短时插值；
- 禁止永久闪烁、粒子背景和持续滚动数字。

### 状态和事件分离

- 状态允许合并为最新值；
- 事件保留顺序、时间和结果；
- WebSocket 断线后通过 REST 快照和事件游标恢复。

### 可访问性基线

目标为 WCAG 2.2 AA：文字对比、键盘操作、清晰焦点、非颜色单一编码，以及地图的列表等价入口。

### 设计系统约束 Codex

所有页面必须使用统一 Token、组件和状态模式。不得在页面内自行创造颜色、阴影、圆角、间距和 z-index。

## 禁止模式

- 满屏霓虹蓝、复杂渐变或玻璃拟态；
- 所有异常都使用同一种红色；
- 只用彩色圆点表达状态；
- 异步操作只显示 Toast；
- 地图标记每条 MQTT 消息都瞬移；
- 加载一个侧栏时锁住整个页面；
- 关键操作只在 Hover 时出现；
- 模态框只有“取消 / 确定”；
- 在 Pilot 2 中直接复用桌面端完整后台。
